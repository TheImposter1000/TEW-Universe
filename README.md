# TEW Universe Studio

Independent Windows desktop editor for **existing** Total Extreme Wrestling IX scenario records.

## Verified numeric code labels

The centralized `TewCodeLabels` catalog translates **403 verified numeric codes** across fourteen database fields, based on mappings supplied by the TEW Universe maintainer. The worker categories are `tblWorker.Gender` (8), `Sexuality` (5), `Pronouns` (5), `Race` (9), `Based_In` (65), `Nationality` (200), `Style` (16), `CompetesAgainst` (5), and `Outsiderel` (4). Tag teams translate `tblTeam.Type` (6). Relationships translate `tblRelation.P_Rel` (9), `R_Rel` (7), and `F_Rel` (7), each beginning at code 0. Worker attributes add `tblAttribute.Attribute` (57 verified code/label pairs covering four groups). Some examples: Gender 5 is Female; Sexuality 5 is Pansexual; Pronouns 3 is They-Them; Race 7 is South Asian; Based In 22 is Manitoba; Nationality 36 is Canadian; Style 13 is Technician Flyer; Competes Against 5 is Primary Women's Division; Outside Relationship 1 is No; Tag Team Type 4 is Inactive Permanent Unit. These mappings are **application labels only** and never change the TEW IX database schema.

Known values appear as readable names in worker profile fields, worker header and Quick Facts, gender/nationality/region roster filters, plus existing-tag-team and new-tag-team type selections. Editors still keep and save the corresponding **original numeric code**, and filters still match the original stored values. Any unknown/unmapped code remains visible as `Code N` rather than being guessed, and other unverified TEW IX numeric categories remain unchanged. The label catalog is presentation-only and performs **no MDB migration or write**.

## Standalone Employment History and worker types

**Employment History** is now its own main navigation section, separate from the Workers profile. It reads the whole `tblCV` table, shows each worker's saved company periods, searches across workers, companies and dates, and supports new periods, updates and removal using the original worker-linked records. The worker selector is mandatory for new periods; selecting a saved period restores its linked worker. Dates retain the TEW IX ongoing sentinel `01/01/1666`. The worker's profile remains separate from historical employment.

**Employment History CSV** now works like a full Championship history spreadsheet. **Export All CSV** creates a simple 10-column table: WorkerUID, RecordName, CompanyUID, Initials, From, Until, Loan, Trade, Tour, Developmental. Edit a row to update it, add a row for a new period, and **remove a row to delete that period from the TEW database** when importing the entire CSV. All rows remain linked to existing workers; CompanyUID / FedUID 0 represents an unlisted historical promotion with no tblFed record. Import previews separate **Add, Update, and Delete counts**, requests a second confirmation if anything will be deleted, offers an optional backup, and applies changes in one Access transaction or rolls them all back. Different workers and even the same worker may share a RecordName when employment periods differ by their exact dates. Indistinguishable completely identical rows remain protected from unsafe individual changes. Older advanced CSV files containing Action, OriginalRecordName and SourceFingerprint remain accepted, including explicit **Action=Delete**. For these older exports, import now asks whether to reconcile the visible rows as a **full replacement** (ignoring duplicate original identity columns) or to apply the older action-based patch rules. This allows already edited legacy spreadsheets to be imported without manually rebuilding them. In replacement mode, removing spreadsheet rows deletes those records, and deletions require a separate confirmation. The main Employment History toolbar also has **Delete Selected** for removing a single entry. Re-export before editing to work from the current database snapshot. Test destructive imports on a copy of the TEW database and run the game's Data Check.

**Worker Types** is shown prominently on each worker Profile. Use **Add worker type** to enable an existing `tblWorker` role flag (wrestler, occasional wrestler, referee, manager, announcer and other roles actually available in the loaded database). Multiple types can be enabled for one worker, and selected roles can be individually unchecked. The original Boolean/numeric flag fields are saved directly through the worker's usual Save Changes button. If the scenario also contains a numeric `WorkerType`, `Worker_Type`, `Role` or `Type` field, its dropdown offers only codes already present in that MDB; unknown codes are never assigned invented descriptions.

## Historic championship stories and contract creation (unreleased)

**Title Lineage → Edit Selected Reign's Champions** lets you change only the holder UIDs and historical display names in a selected `tblBeltPreHistory` record. **Title Lineage → Insert Historical Reign** adds one dated record without deleting or regenerating the existing reigns; the selected title's `BeltOrder` values are re-numbered chronologically, transactionally, while existing holder IDs, names, capture/loss dates, defenses, UIDs and record names remain unchanged. Both actions offer an optional backup. Selecting No proceeds without one, and Cancel stops the write. Singles, tag-team and trios title formats use each holder's actual worker UID or **-1 + a historical name** for a name-only NPC. Name-only people are not added to `tblWorker` or `tblTeam`. Examples: Carson and an NPC father may appear as the two tag-team holders; Tavitia and Damien Ward may be recorded as successive historical champions around 2014. Match opponents who did not hold the title are not stored by the title lineage schema.

A new `Workers → Contracts → Create Contract From Template` action can insert one `tblContract` row for the selected existing worker. The user chooses a real existing company and then a real contract from **that same company** as the template, reviews the source fields, and can edit supported terms, including boolean values. The application copies the actual stored template values rather than guessing undocumented TEW IX enum defaults, replaces the worker link and allocates a unique contract UID / Recordname. It refuses a duplicate worker/company pair or incompatible schema, and offers a backup choice (Yes / No / Cancel) before final confirmation. It does **not** modify the source contract or create historical `tblCV` employment. Copying a template is not the same as verifying the business correctness of every original field: use a copied scenario and TEW IX Data Check before relying on these inserts.

**Pending, not mapped:** Body Shape was supplied as 1 Average, 2 Skinny, 3 Toned, 4 Muscular, 5 Ripped, 6 Flabby, 7 Bulky, 8 Obese. An earlier audit observed `tblWorker.BodyType` values 0–7, so those labels are intentionally **not** bound to `BodyType` until the offset is verified. The app must not mislabel code 1 as Average if its actual meaning is different.

## Company opening/closing dates now correctly constrain generated title histories

TEW IX's `tblFed.CompanyOpening` and `tblFed.CompanyClosing` are **full dates**, not merely an opening/closing year and month. The generators now use these precise fields when present, with legacy year/month fallback for other compatible MDB layouts. A closed company stops on its actual closing day. **Heartland Championship Wrestling (company UID 403)**, for example, has an opening date of September 7, 1996 and closure of March 28, 2020. Selecting HCW in the Advanced Generator with **Respect company dates** checked now limits a requested 2007–2021 championship history to **2007–March 28, 2020**. The first reign is similarly prevented from beginning before an exact company opening day.

A championship with an empty `OriginalFed` must no longer silently generate beyond its company closure. Both the original lineage generator and the advanced generator have a historical company selector. In the Advanced Generator, the selected **Company for dates and employment** is used for *both* chronology constraints and worker-employment checks. The effective date window is displayed before generating and updates as company/dates change. If no company is known and company constraints are enabled, the generator requests an explicit company selection. Users can deliberately disable company constraints to use a manual final date, while the scenario start remains a hard cutoff.

## Shared CSV import/export across Studio sections

**Export Record CSV** and **Import Record CSV** appear in the main toolbar whenever a supported non-worker record is selected. The shared workflow covers **Companies, Titles (championship details), Tag Teams, Events, Stables, Awards (both global and company awards), and Relationships**. It exports the actual selected record's supported scalar fields, preserving the section name, source table, record UID, field types, original values and editable flags. Modify only **Value** and import it into the *same selected record*. The importer previews differences, rejects stale/mismatched files and protected identity edits, asks for explicit approval, then calls that section's existing validated database writer. Backups remain optional.

New **ExistingEditors** record-backed sections automatically receive the shared CSV workflow when registered, rather than needing a duplicated CSV import implementation. Bespoke future sections need a verified record adapter and safe write rules before CSV editing is enabled; no unknown table is made writable automatically. **Workers are intentionally excluded.** Tools is a diagnostic report rather than an editable record section, so its existing report CSV export remains available without a nonsensical CSV import. Championship *history* remains a separate specialized CSV flow; the shared Titles CSV edits championship details, not entire title lineages. Company CSV retains its original company-specific format for compatibility, with the shared toolbar actions opening that importer.

## Company-scoped CSV and attached current roster

Inside **Companies**, select a promotion. **Export Selected Company CSV** writes the company's current scalar field values and uniquely linked one-record company settings to a UTF-8 CSV file. The format includes **CompanyUID**, **CompanyName**, source table, record key and ID, field type, original value, editable flag, and **Value**. Edit **Value** only, then choose **Import Selected Company CSV** to validate and preview the differences before confirming the database write. CSV files for other company UIDs, stale source values, changed identity columns, and edits to protected fields are rejected. The import uses the same transaction-safe company editing path. Multi-record company sub-tables are still read-only; roster/contract assignment is not imported by this format.

The **Current Roster** section lists workers with actual **tblContract.FedUID** links to the selected promotion, showing their worker UIDs, active flag, and contract counts. Search the company roster, open a worker in the Workers editor to inspect or edit their actual contract, or export the roster as a separate read-only CSV report. This is the scenario's current contracted roster, not historical **tblCV** employment. A CSV import never creates new workers or assigns/terminates contracts. This distinction is deliberate: contracts have their own database identities and verification rules.

## Comprehensive company editor

**Companies** now loads **every available tblFed column** from the active MDB, rather than silently showing only a few preselected fields. The interface groups identity, operating dates, business/finances, presentation/product, personnel/policies, geographic settings, and remaining TEW IX fields into expandable sections. Supported scalar settings are editable. Primary and internal record identities, unknown relationship references, and non-scalar database values are visible but read-only; codes are never assigned speculative descriptions.

The screen also discovers verified **FedUID-linked** company records in `tblFedOver` (regional popularity), `tblFedStyle`, `tblFedHiring`, `tblFedBackstage`, `tblFedBio`, `tblFedPower`, `tblFedTour`, `tblFedSchedule`, `tblFedBrand`, and `tblFedDept`. Linked single-record tables expose supported scalar edits; multi-record tables use read-only grids because assuming a unique row would risk corruption. Changes across the primary company and verified related records are validated before writing and committed in one transaction. Any missing table or unverified relationship is reported in the interface, not treated as an empty writable record. This adds full visibility and safe editing to currently known company records; it is not a promise that every TEW IX relational subsystem can be reconstructed or edited.

## Scenario start and company-aware championship dates

Studio now reads the scenario start from **tblInfo.StartYear / StartMonth** rather than estimating the start from the computer clock. Use the new toolbar action **Scenario Start...** to view or edit the game-wide month/year; changes go to the selected scenario MDB after explicit confirmation and an optional backup prompt. TEW IX supplies no day-of-month here, so the game start is treated as the **first day** of the chosen month. Generated pre-game reigns cannot extend beyond the **previous day's** date. This does not automatically change any existing title history.

The **Companies** editor now permits updates to the verified **OpenYear / OpenMonth / ClosedYear / ClosedMonth** fields with validation. The title-history generators read these fields for the championship's **tblBelt.OriginalFed** company. When **Respect company dates** is selected (the default), generated history begins no earlier than the company's opening month and finishes no later than the closure month's final day. A company recorded as closing in November 2021 therefore ends its generated title history on **November 30, 2021**, not December 31. If no closure is recorded, the scenario cutoff or selected end year applies. For an active championship when the scenario starts in June 2022, the latest possible pre-game date is May 31, 2022.

Both generators provide an optional **Final date** (numeric or written, e.g. `5/12/1998` or `May 12th 1998`) for more exact endings and a checkbox to override company date constraints while preserving the scenario's absolute cutoff. The preview displays the effective dates. Annual tournaments reject events beyond the legal cutoff rather than fabricating a late winner. These constraints affect newly generated previews only, and do not modify existing company or title history unless a user explicitly saves/imports changes. The historical data model stores company opening and closure as **months and years**, so an exact mid-month closure requires the manual final-date override.

## Championship history CSV import

Select a championship, then choose **Import History CSV** from **Title Lineage** or **Advanced Generator**. The file is parsed in memory and opened as a full-height preview; no database write occurs while opening or validating a CSV. The import accepts the three column layouts already exported by Studio: original title draft (9 columns), advanced full-history draft (11 columns), and targeted holder changes with a history UID (12 columns). Dates may use US numeric month/day/year (`5/12/1998` or `05/12/1998`) or English month names (`May 12th 1998`); exported CSV remains `MM/DD/YYYY`. The file must identify the selected BeltUID. Championship member counts, name-only NPC positions (UID -1), actual linked workers, chronological title reigns, and annual tournament sentinels are checked. The importer refuses wrong-title files and unexpected column layouts rather than assuming a mapping.

Full draft import rebuilds the selected title's history and allocates new history UIDs; **it is not a UID-preserving restore**. A targeted-holder CSV instead updates only name-only existing reigns whose UID, order, capture/loss dates and defenses still match the current database. Already-linked champion rows cannot be overwritten by this targeted import. Both routes reuse the existing explicit import confirmation and optional-backup choice. Validation is not a guarantee that the TEW IX game will accept a modified MDB; test with a database copy and run the game's Data Check. Import supports Studio-exported championship history CSVs, not arbitrary spreadsheets or CSVs from other applications.

## Championship history: optional backup and defense realism

Importing a **full championship history** no longer requires users to click **Create Backup** before applying the preview. Import confirmation still explicitly identifies the title, how many prior entries will be replaced, and that the write targets the active MDB. A separate **Yes / No / Cancel** choice allows users to back up, continue without backing up, or stop. Existing championship edits, new historical reign insertion, and generated replacement also use this optional workflow. The Create Backup toolbar action remains available at any time. Database schema checks and transactions are unchanged.

Historical defenses now scale with the number of days a title is held rather than awarding nearly every long reign an implausible count below 25. **Title Lineage** and **Advanced Generator** both include a **Defense frequency** setting with **Automatic**, **Touring**, **Television**, **Regular**, **Occasional**, and **Special attraction** profiles. Automatic recognizes Television/TV titles as frequently defended, World/Heavyweight/Universal titles as touring, and other names as regular. Users can override every title's frequency without editing the TEW MDB schema. A 438-day Television reign typically produces dozens to well over 100 defenses instead of around 11. Reigns receive different randomized rates, with no credit for the championship-winning or losing matches; the planner never changes the winning years or protected reign lengths. **Annual Tournament / Cup** histories still store -1 defenses and no continuing title reign. The counts are historical estimates, not verified match-by-match results.

## Dual-purpose partner text boxes (next update, PR #19)

For Tag Team and Trios history entry, each partner has an **existing worker** dropdown and one adjacent **name field**. When the dropdown is empty, a name is **required** and identifies a name-only historical NPC (holder UID `-1`), available in Build new full history. When a real wrestler is selected, the same field is an **optional ring-name alias** for that person: leaving it blank uses the worker's existing name, while typing a different name retains the real positive worker UID. Dynamic field labels and tooltips clarify which interpretation is active.

## Worker roster filters

The **Workers** sidebar has a collapsible **Filters** panel alongside the existing name/UID search and Name A–Z / Z–A / Worker ID sorting. Filters combine with **AND** logic and update the matching count and worker list immediately. The available controls are: **Active / Inactive**, **Gender**, **Age minimum/maximum** (inclusive, calculated from the worker's `tblWorker.Birthday`), **Current Company** (from live `tblContract.WorkerUID → FedUID` links, including No current contract), **Worker Type / Role**, **Nationality**, **Based-in Region**, and **With pictures / No pictures**. **Reset** clears every filter and the name search to restore the full roster.

Filter values are loaded in a single batch from the selected TEW IX scenario, not from guesswork. Role choices come only from worker-role columns actually found in its `tblWorker` schema; filters unavailable in that MDB are disabled with a short explanation. Verified Gender, Nationality and Based In codes display the app-only labels above while their filter keys remain the original numeric values. Unknown or unsupported codes continue to display as **Code N**. No unverified enum translation is invented. The company filter reads **current contracts**, not historical `tblCV` employment. Portrait presence tests whether a matching file exists in the configured worker-picture folder (or its People subfolder) using the name-first, MDB-filename-fallback rule of the portrait renderer, so blank `Picture` fields can still have a picture. If no picture folder is set, the panel explains why everyone appears to have no configured portrait. Filtering is read-only and never changes the MDB.

## Worker Attributes and Employment History

The **Workers** editor has two additional worker-specific tabs: **Attributes** and **Employment History**.

**Attributes** reads actual `tblAttribute` rows linked by `WorkerUID` and shows verified names plus numeric codes, or unmapped codes when names have not yet been established. The dropdown offers named verified values; **Unassigned** codes cannot be added, and existing unmapped values can only be retained unchanged. The actual MDB type determines whether values are numeric or text. `Hidden` / `Permanent` remain independent Yes/No flags. Add, Save Selected and Remove require explicit confirmation, and worker links and other attribute records are preserved.

**Employment History** reads `tblCV` (not `tblContract`) and displays historical company periods with their actual `FedUID`, company initials, `CVFromDate` / `CVUntilDate` and Loan / Trade / Tour / Developmental flags. The **Company** selector and **Historical company initials** field are synchronized: picking an existing company fills its *actual* `tblFed.Initials` (even when initials were already entered); typing a unique, case-insensitive initials match selects that existing company automatically. Blank, partial, unknown or ambiguous initials never silently select an incorrect promotion. The form displays a matching hint; existing historical initials are preserved when loading a saved period rather than silently rewriting history. Users can add, update or remove individual periods, selecting a real company or entering initials and dates for an unlisted company (FedUID 0) without creating a promotion in the scenario. A dedicated **Unlisted historical company** checkbox can override initials auto-matching. Positive company UIDs must reference a real tblFed record; negative UIDs are invalid. Transactional writes preserve each historical period. Writes are transactional, confined to the selected worker, and always require explicit confirmation; manual backups remain recommended but optional.

These are direct scenario MDB modifications, so test a copied scenario with TEW IX Data Check before editing important data. The UI does not create active contracts, new workers or companies. Attributes and employment periods have their own Add / Save Selected / Remove actions rather than the main worker scalar-field Save Changes button.

## Tag Teams module

The sidebar now includes **Tag Teams**, integrated into the existing three-column workspace. You can search existing `tblTeam` records, edit their supported fields, and select linked workers and companies from actual `tblWorker` and `tblFed` records. Team type dropdowns show the verified names for codes 1–6 while retaining the **raw numeric codes** for reads and writes. Available type options are still drawn from existing teams in the selected MDB.

**Create Tag Team** opens a dedicated editor for a pair of existing workers, company-specific or game-wide affiliation (using only None codes observed in this MDB), team-type code, experience, formation, finisher, and active state. A manual backup is optional: when creating a team, **Yes** creates a backup, **No** proceeds without one, and **Cancel** stops. The app validates the MDB schema, linked IDs and duplicate partnerships, then inserts exactly one new `tblTeam` row transactionally, allocating a unique UID and Recordname. Unsupported mandatory schema fields block creation; no tables besides `tblTeam` are modified.

This initial module must be tested in TEW IX's Data Check using a backed-up scenario before editing your main scenario. Its form fields and mappings may be adjusted as MDB-specific details are validated.

**Repair record names already saved in your MDB (not just new records):** Open a title's **Title Lineage** tab and use **Review / Repair This Title's Record Names** or **Review / Repair All Title Record Names**. In a worker's **Employment History** form use **Review / Repair This Worker's Existing Names** or **Review / Repair All Employment Record Names**. A dark preview shows old and proposed `RecordName` values side by side, including unchanged/unsupported records and any warnings. Nothing is written until the user explicitly confirms the preview. Existing `tblBeltPreHistory` names become `Title Name001`, `Title Name002`, etc., numbered by `BeltOrder`; existing `tblCV` names become `INITIALS (YYYY-YYYY)` for completed jobs or `INITIALS (YYYY -?)` for ongoing ones. Repeated same-year Record Names are valid for the same worker when the exact employment periods can be distinguished. Only physically ambiguous source identities are skipped with warnings, including for FedUID 0 entries. Already-correct names are skipped. Missing initials, unknown starting years or unclear record identities are flagged and remain unchanged, not guessed. A verified `01/01/1666` ongoing **Until** is supported; other unknown dates are not inferred. The migration updates **only the Recordname/RecordName text column**, preserving record UIDs, title IDs and order, actual title holders, capture/loss dates, defenses, worker and company links, employment dates and flags. To handle cross-renames safely, the write uses unique temporary names and finishes inside a single transaction; stale previews are rejected. A manual backup is offered but optional before applying record-name repairs. Test a copied TEW IX MDB before relying on this migration.

**TEW IX 01/01/1666 ongoing date:** TEW uses January 1, 1666 as a sentinel for an **ongoing ending date**, not an actual closing or finishing date. A company's `CompanyClosing=01/01/1666` means it remains open. A historical employment period with `CVUntilDate=01/01/1666` remains ongoing and is stored unchanged in the MDB, while the Employment History list displays **Ongoing**. The editor provides **Still active (01/01/1666)** next to Until and supports manual entry of the same value. The record-name generator uses `DNA (2022 -?)` rather than `DNA (2022-Present)`; existing-record rename previews also use this spelling. **From dates** must still be real dates. Tag teams use an independent **Active** flag, and the **Formed** date is not an ongoing ending date. Other contexts, such as the special annual tournament title-loss sentinel, preserve their separate meaning.

**Employment Record Name conventions:** An ongoing historical period uses `DNA (2022 -?)`, while a completed period uses `NCW (2016-2020)`. The punctuation intentionally differs. This affects historical `tblCV` entries, not the separate active contract table.

**Employment Record Name validation:** The Generate name action reports the exact missing or invalid initials, From date, Until date, unsupported year, or reversed date range inline below the Record name field and focuses the affected input instead of displaying the same generic popup for every case. Both dates are still required for the `INITIALS (YYYY-YYYY)` identifier, except that the Until field may use TEW's known `01/01/1666` ongoing sentinel, which produces `INITIALS (YYYY -?)`. The generator never guesses missing historical dates. A selected company's real stored initials can supply a blank initials input.

**Readable title and employment record names:** Newly rebuilt full championship histories use the title's actual `tblBelt.Name` plus a three-digit reign number, such as `BCW Championship001`, `BCW Championship002`, etc. Existing title history identifiers are NOT mass renamed. A new historical employment stint uses `INITIALS (YYYY-YYYY)` in `tblCV.RecordName`, e.g. `PWA (2015-2021)`, and does not automatically append `#2` for repeated year-range labels. Workers may have multiple one-month handshake stints in the same company and year with identical generated names; the editor distinguishes them using the original company, exact start and end dates, and stored field values. The Employment History form has an editable **Record name** field before the company dropdown, plus a **Generate name** button. Changing an existing record's name is an explicit, worker-scoped transactional update. Manual names are checked against MDB text length; repeated year-level labels are allowed for distinct stints.

**Workers → Contracts:** A new **Contracts** tab appears immediately before **Employment History**. It reads linked live `tblContract` entries, with the active company (when its reference is present) and a full per-record field inspector. Supported existing scalar columns may be edited through **Save Selected Contract** after confirmation; the record identity, linked worker and unverified foreign keys remain protected. This intentionally does not create/delete active contracts, whose complete mandatory schema has not been independently validated. Historical `tblCV` periods stay separate. The attribute, contract and historical employment grids now use consistent dark headers, rows, cell selection and text styling rather than the WPF white default.

**Date entry and display:** Editable dates accept numeric US month/day/year (for example **5/12/1998** or **05/12/1998**) and written English dates (**May 12th 1998**, **May 12, 1998**, or **May 12th, 1998**). Ordinals must be correct (1st, 2nd, 3rd, 12th), and invalid calendar dates are rejected. Display, confirmation messages, and CSV export remain consistently **MM/DD/YYYY**. Year-first **YYYY-MM-DD** is not accepted for manual input. Worker date pickers still use Month / Day / Year selections. The MDB continues to store native DateTime values; chronology and year-only history settings are unchanged.

**Visible tag-team dropdown selections:** The shared dark WPF ComboBox template now supports editable text via `PART_EditableTextBox`, preserving selected worker, company and team-type labels while allowing typed searches. The existing Tag Teams editor and Create Tag Team dialog explicitly render the option labels. This is a display and input fix; it does not change saved team IDs or modify MDB data.

## Corrected Awards, Accomplishments and Data Check

**Awards:** Actual TEW IX category fields such as `MaleOverall`, `FemaleOverall`, `MaleTag1`, and `FemaleTag2` are now recognized as selectable worker recipients in BOTH global and company year-end award tables. Winner editing uses editable name-search dropdowns rather than raw read-only UID fields. Save and Create actions are visible above the long category list, with technical data collapsed below it. A dedicated Create New Award Year dialog assigns the new year's recipients independently, starting unassigned, while required unchanged database metadata comes from the selected existing record. Match/show-of-year details are reset to neutral values when their field types are supported. New rows have a new UID and unique Recordname where present. Existing recipients and records are preserved. Unverified numeric columns are never treated as worker UIDs. World award years cannot duplicate an existing year's consolidated record; company awards may share a year across promotions. Validate writes using TEW IX Data Check on a disposable scenario copy.

**Workers → Accomplishments:** A **read-only company-grouped career view** displays each promotion's championships with `×N` reign counts and optionally expandable capture dates, similar in structure to a titles-and-accomplishments profile. Below that, an **Awards & Other Accomplishments** section lists actual global and company year-end award wins using readable category names and years. The view is derived from `tblBeltPreHistory`, `tblBelt`, `tblEOYAward` and `tblEOYFedAward` when opened; it does not infer match participants from unverified free-text columns or fabricate achievements from biography claims. It does not write to the MDB or previous local JSON data.

**Workers tab layout and Tools:** All nine worker tabs now use two readable rows rather than clipping text in a three-row space sized for two. Biography/team comparisons in Tools require explicit team-affiliation phrasing, so incidental phrases such as `the Elite Division` and `the family mask` no longer trigger reports for teams named `The Elite` or `The Family`. Selecting a Data Check finding shows its full explanation without horizontal truncation. This is deliberately a conservative text heuristic, not a claim to understand every biography.

The checker preserves ambiguity: a word or number merely near a championship name is not a reliable title-reign claim; direct numerical phrasing is required for biography review findings. Data Check can open a referenced existing worker directly or copy the complete finding. Findings are cleared on database switches, and the UI distinguishes `Not yet checked` from a completed scan with zero findings. The scanner is read-only and does not replace TEW IX's own Data Check.

## Workers → Accomplishments (read-only automatic career record)

The ninth Workers tab now looks like the Biography editor but is **read-only**. It automatically displays the worker's linked pre-game championship reigns and world/company year-end award wins recorded in the active TEW IX scenario MDB. It refreshes from actual title/award data when a worker is selected or the tab is opened. There is no manual entry, no custom achievement creation, and no extra user maintenance required.

The former Studio-only JSON editor has been retired from the screen. Existing JSON files under `LocalApplicationData/TEWUniverse/Accomplishments` are preserved on disk rather than deleted, but are no longer displayed as if they were official game history. The summary never writes to the MDB or old JSON.

This is a factual summary of *linked recorded pre-game* award/title data, not a text guess from biographies or an extraction of in-game saves. Unverified award fields and historical name-only champions without linked worker IDs are not attributed to a worker.

## Tools: Studio Data Check (mini-update 2 of 3)

**Tools** is now a working read-only diagnostics workspace, with **Run Data Check**, searchable and severity-filtered findings, a CSV report exporter, and shortcuts to Workers, Titles / existing record-name repairs, and Awards.

The checker compares actual `tblWorker` records with `tblTeam.Worker1/Worker2`, linked holders in `tblBeltPreHistory`, and positively verified award recipient fields in **both** `tblEOYAward` and `tblEOYFedAward`. Missing positive worker/company links and self-partnerships are marked **Error**. It also detects duplicate consolidated world award years, suspicious company/year duplicates, and duplicate partners in tag team award fields. Duplicate same-company tag-team pairs are marked **Review** because an inactive alternate team could be legitimate. Missing required table columns are reported as **Unavailable** rather than silently treating the scan as passed.

It also reads workers' `tblWorkerBio.Profile` and flags carefully detected claims such as "3-time [actual title name] champion" when the recorded pregame title lineage has another number of linked reigns. Mentions of a known tag team not linked to the biography's worker also become **Review**, not errors. A biography can refer to another promotion, a former partnership, a non-pregame period, or in-game history. There are **no automatic fixes** and no MDB writes. Missing/unreadable tables are surfaced as **Unavailable** rather than silently treated as clean.

The Tools results are an additional consistency check, not a replacement for the TEW IX Data Check or a complete interpretation of arbitrary natural-language biographies.

## Awards: world and company year-end records (new)

**Awards** replaces the inactive History sidebar placeholder. It browses the real `tblEOYAward` (world) and `tblEOYFedAward` (company) tables, with a switch between them, searchable year/UID/recipient information, and a full inspector showing every original MDB field. Known global award winner IDs display the matching real worker name; known company winners display the matching company name. All database columns are introspected at runtime rather than assuming the two tables share identical fields.

This first Awards release allows **editing existing years and selected recognizable world-award worker/company winner references only**. Records with unrecognized field layouts stay read-only. Inputs use the actual MDB column type; updates enforce real positive worker/company IDs, compare the complete original row snapshot, reject duplicate world-award years, and save just the selected row in a transaction. Unknown winner categories, name-only special cases, and unverified company-award fields are protected. Creating new world/company award rows is not enabled until their complete schema and expected defaults are verified. This prevents corrupt or mislinked records and keeps existing awards unchanged during installation.

This is separate from the existing Workers → Employment History and Titles → Title Lineage features, neither of which is removed. Verify any new edits on a **disposable copy** of the scenario and run TEW IX Data Check. This is mini-release 1 of 3; Tools Data Check and Studio-only Worker Accomplishments follow as separate features.

## Historical championship edit: preserve unknown defence counts

**Titles → Title Lineage → Edit Selected Reign's Champions** preserves the
selected historical reign's UID, capture date, loss date, `Defences`,
`BeltOrder` and record name. TEW IX uses `Defences = -1` to mean
unknown/not recorded for **regular championships as well as tournaments**.
It is not invalid data. The editor now validates holder IDs and historical
display names, then checks that the other row values are unchanged, instead
of rejecting the existing -1 count.

**Insert Historical Reign** separately validates new dates and accepts either
`-1` (unknown defenses) or any nonnegative defense count. Counts below -1,
overlapping dates, and invalid new championship date ranges remain rejected.
Annual tournament wins continue to require the 1666 loss-date sentinel and
-1 defenses.

For each champion the edit form identifies whether the existing holder was
a linked worker or a **name-only NPC (UID -1)**. The final confirmation shows
the exact new linked worker IDs and separately warns whenever a worker link
changes. A displayed historical name alone does **not** link an NPC to a
roster wrestler. Always edit a COPY of your TEW IX database first and run
the game's Data Check after verifying this feature.

## Desktop application

The published Windows app now uses **WPF and .NET 8**. Its source is in `src/TEWUniverse.Desktop`, sharing the existing Access data layer and settings from `src/TEWUniverse.Studio`.

The worker portrait feature looks for a **worker-name PNG first**, then WebP/JPEG/GIF/BMP files in that order, in the configured local pictures folder or its `People` subfolder. If no usable worker-name image exists, it falls back to the stem of the worker's `tblWorker.Picture` filename, with PNG still preferred. Missing images show the silhouette; loaded images hide the silhouette and its background, preserving PNG transparency. Portrait loading never edits the MDB or image files. WebP requires a compatible Windows image codec.

Gender, Sexuality, Pronouns, Race, Nationality, Based In, Wrestling Style, Competes Against and Outside Relationship use verified label dropdowns when their stored codes are recognized, preserving the original numeric values in the editor and MDB. Unknown values remain editable raw codes. Boolean flags such as Active remain Yes/No controls.

The redesigned Workers screen includes a sidebar, searchable worker list, real MDB fields, biography editor and status bar. Companies, Titles (championships), Events, and Stables now have existing-record editors in the same dark workspace. These sections browse existing MDB entries and allow updates to a restricted set of fields. Relationships is implemented; Awards replaces History with world/company year-end award records. Tools remains a placeholder pending a dedicated Data Check workspace.

In Titles, open **Title Lineage** to view existing pre-game reigns from `tblBeltPreHistory`, filtered by the selected championship and sorted by Order Number where the MDB schema identifies it. A Generate Title Reigns panel lets you select a pool of existing workers, reign count, years and singles/tag-team mode, then generate a dated preview and export a draft CSV. You can replace holders and dates ONLY when the selected championship already has exactly the same number of prehistory rows; this updates only that belt's existing history UIDs in one transaction. Nothing is inserted or deleted. A backup is offered but optional before replacing lineage; the exported draft CSV is not a verified TEW IX import file. If the belt-reference column cannot be recognized unambiguously, the app shows diagnostic columns rather than mixing reigns across belts.

Titles now also includes an **Advanced Generator** tab: select existing workers by UID (optionally using historical ring names) or add historical name-only champions with `Holder1=-1`. Specify their eligible years in the company and the exact number of required reigns. The planner reserves these reigns within their eligibility windows, then can fill the remaining slots using eligible background holders loaded from the selected title's existing MDB history. A preview and CSV export work for any proposed number of reigns; applying the draft is restricted to the existing rows of that championship, without inserting records. This advanced generator currently handles singles histories. A manual backup is recommended but optional before replacing records.

**Cross-title tournament chronology:** In the Advanced Generator's Superstars section, the checked-by-default **Schedule title wins after the wrestler's recorded tournament victories** option reads other titles marked **Annual Tournament / Cup** in the active scenario. For each fixed championship-winning year, a matching worker UID and recorded tournament victory in that SAME year constrain the generated title capture to occur AFTER the tournament date. A May 2020 Cup victory therefore prevents that wrestler's 2020 Junior Heavyweight championship run from starting in January. The preview identifies the supporting tournament and date. Disabling the option restores the unconstrained dates; name-only NPC histories (Holder1=-1) cannot be linked reliably and are ignored. Only preview dates for the currently selected title change; other existing lineage is read-only. If the constraints cannot fit in the selected calendar year, generation reports an error rather than quietly violating the chronology. This is an optional storyline rule, not an assumption that winning every Cup guarantees a title reign.

**Singles, Tag Team and Trios lineage formats:** Under **Titles → Championship Details**, the second studio-only classification dropdown (next to Championship / Annual Tournament) chooses how many linked real-worker holders a reign needs: **Singles (1)**, **Tag Team (2)** or **Trios (3)**. The format is stored in local application settings for the selected database/title, not written as an invented TEW IX belt code. Tag and Trios entries accept a primary wrestler plus partner worker UIDs; each member must be a different existing worker. Until full group-history generation is implemented, new full-history building remains singles-only; Tag Team and Trios use the safe existing-lineage substitution workflow.

**Add known champions to an already complete title history:** For a title with existing `tblBeltPreHistory` rows, the Advanced Generator defaults to **Replace only name-only/unused reigns (preserve dates)**. A requested **four-time** champion such as Carson Cade takes up to four eligible name-only placeholder reigns; reigns already linked to Carson count toward his four, so existing champion records are never duplicated or overwritten. Exact winning years and requested day/month/year lengths restrict which existing slots qualify. If no matching unused slots exist, preview fails with an actionable error. Only the chosen existing slot **Holder1/2/3 IDs and names** change; original capture/loss dates, defenses, reign order, UIDs, unrelated NPC slots and linked real-worker champions remain intact. A separate explicit **Build new full history** mode still exists for intentionally rebuilding a singles title (and annual tournament, singles-format winner histories). The importer uses a transactional identity-checked, holder-only UPDATE and a clear confirmation distinguishing patching from deletion/rebuild.

**Employment-history validation:** Both previews compare a linked champion's **full title tenure** with `tblCV` employment for the title's company. The **Employment-check company** selector defaults to `tblBelt.OriginalFed`, but lets you override that when a belt has changed promotions. A reign is marked **Covered** only if documented employment (including contiguous stints) spans the entire capture-through-loss period. Missing CV periods, unknown companies and historical date sentinels are distinctly flagged, not silently ignored or used to change a title's dates. Annual Cup winners are checked on their winning day. Warnings are repeated before importing; backing up first is recommended but optional.

**Flexible superstar reign counts, winning years and durations:** The **Titles → Advanced Generator → Superstars** grid lets you specify a wrestler's **Reigns** independently of **Years won**. Repeated years are valid for ordinary championships (e.g. `2016, 2016` for a title-trading feud); the generator inserts another champion between separate reigns. A 14-time champion does **not** need 14 different years. Enter only the years you know, in chronological order; `-` represents an automatically assigned year in a particular slot and omitted later slots are also filled automatically within the wrestler's **Active from / until** years and the title's history range. Annual Tournament / Cup mode still permits one winner per edition and requires a distinct year for each real-worker Cup win.

**Reign lengths are independently optional per victory:** enter `719d` for EXACTLY 719 inclusive days. Enter `2y` for **at least two calendar years**, with up to 90 additional days when compatible with other known wins; `6m` means **at least six calendar months** plus up to 30 additional days. These are intentionally *approximate* calendar requests, whereas `d` is an exact day count. Specify `2y` for only the first of six reigns and leave the remaining lengths unspecified, or use `-, -, 2y` to target only the third. Other reigns retain randomized lengths. The generator will not truncate a protected tenure to insert an NPC or another known winner and reports infeasible conflicts. The preview shows requested vs actual tenure, and importing remains a separate confirmed action.

**Optional championship starting month:** The Advanced Generator's NPC History section offers **Starting month (optional)** for regular championships. **Default (January)** keeps January as the opening month, but the first championship reign now begins on a **random day** within that month. Selecting June with From year **2002** places the initial PWA World Heavyweight Championship reign on a randomized June date, never before Pinnacle Wrestling Alliance opened. Both the inaugural NPC history and any pinned real-worker wins in the first year respect that boundary; later years and cross-title tournament chronology still work normally. The preview states the resolved first allowed date. Annual Tournament / Cup titles continue to use their separate recurring event month, week and weekday, so the championship-only start selector is hidden for them. The Through year still ends December 31; this change does not add an optional end date. If the first-year schedule cannot fit the pinned wins after the chosen month, the generator rejects it rather than moving them earlier. No existing MDB history changes until you import the preview.

**Varied championship reigns:** Standard championships no longer automatically change hands on January 1 or award every champion an identical year-long reign. The Advanced Generator now picks variable durations—including a few weeks, several months, and occasional reigns lasting more than a year—while preserving every fixed winning **year** supplied for a real superstar. The number of generated reigns emerges from this chronology, instead of one history entry per calendar year. Defence counts are also varied independently of reign duration. The preview shows days held and a short/medium/long breakdown. The older fixed-count generator also allocates its requested number of reigns across uneven durations. **Annual tournaments** produce one winner per year on a date calculated from a recurring schedule (month, first/second/third/fourth/last occurrence, weekday), without a title-loss reign or defences.

**Expanded title editing:** Additional `tblBelt` fields are now real editable controls rather than a read-only list. Settings such as **Annual Title**, **Annual Type**, **Tour Frequency**, **TV Frequency**, **Retain Title**, **Achievement**, **Valid Matches**, and **Belt Lock** can be changed using their stored MDB data types when present. Title UID, internal record names and unknown foreign-key fields remain protected. **Original Fed** and **Card UID** accept existing linked IDs (with zero / -1 unassigned sentinels), checked against `tblFed` or `tblCard` before saving. All edits use the normal Save Changes transaction and pending-change tracking. No automatic backup is created; Create Backup is available on demand and remains optional. Title Classification is still a separate cosmetic setting saved locally, not a fake TEW IX enum.

**More varied annual tournament winners:** The Advanced Generator no longer restricts historical Cup NPCs to roughly one recurring name for every three editions. Where `tblGenerateWorker` supplies enough eligible names, at least 75% of NPC-winning editions use **distinct** historical names; the remaining editions allow occasional repeat winners. Repeat wins prefer previously less successful entrants and avoid the last two editions where possible. Fixed superstar victories keep their linked worker UIDs and exact winning years, and tournament dates are unaffected. If the generated-worker source or optional race/gender filters provide too few names, repeats remain necessary and the preview reports the available diversity. Preview also displays the count of distinct NPC winners. Existing title lineage changes only when the user explicitly imports the generated preview.

**Championship vs. annual tournament:** Title Details now has an app-only **Title Classification** selector for each championship UID in each scenario database. The label is saved locally in TEW Universe Studio settings, not written into `tblBelt`. **Championship** continues to show reigns, loss dates, and defences. **Annual Tournament / Cup** represents one winner for each annual edition: the generator asks for the event month and weekday occurrence (for example, the first Sunday in March) and computes `BeltCaptured` separately for each year's edition, and uses the title-history no-reign conventions visible in existing TEW IX data (`BeltLost = 1666-01-01`, `Defences = -1`). The lineage table displays winners rather than treating them as champions with year-long reigns. The old reign-based generator is blocked for tournament-classified titles. The title editor also includes an expanded read-only inspector of other `tblBelt` fields and additional allowlisted descriptive fields; IDs and foreign key relationships remain protected. This is a Studio display classification, not an assertion that TEW IX stores these types itself. Test generated tournament history on a backed-up scenario before writing to the primary MDB.

**Two-section history generator:** In **Titles → Advanced Generator**, the top **Superstars** section contains only linked workers, their optional historical ring names, active years, total reign counts, partially specified winning years (including repeats), and independently optional reign lengths. The lower **NPC History** section contains just the historical start/end years and optional race/gender codes; there is **no NPC reign-count field**. The generator automatically creates a name-only NPC winner in each year without a pinned superstar victory, drawing names from `tblGenerateWorker` and never adding workers. For example, a cup that began in 1994 with Kaito Moriyama's sole 2020 victory produces a full chronology across the chosen years, not a one-row preview. Rebuilding the selected belt requires confirmation and successful schema checks; making a manual backup first is recommended but optional. History inserts have not yet been validated in-game.

**Fixed-win history builder:** The Advanced Generator now accepts exact championship-winning years for linked workers, for example `2016, 2017, 2019` for Dragonheart (`#4975`). It reads name-only NPC candidates from `tblGenerateWorker`, optionally filtering by stored race/gender codes, and generates a chronological sequence with NPC champions before, between, and after those fixed wins. NPC champions are written with `Holder1=-1` and a historical display name; no NPC is added to `tblWorker`. The preview shows the implied predecessor and successor of each champion. A full rebuild can **DELETE the selected championship's old `tblBeltPreHistory` rows and INSERT any requested number of new rows in one transaction** (other championships and workers are not changed). The **Import Preview to Title Lineage** action performs this destructive replacement for the selected title only, recommends an on-demand **Create Backup** but requires only explicit destructive confirmation, then opens the saved Title Lineage view so the results are immediately visible. The table schema is validated at runtime, and unsupported schemas fail without writing. Validate a test database with TEW IX's Data Check before editing production data.

**Direct database editing:** Select an existing scenario MDB as the **Active Database**. Save Changes writes to that same file; Refresh Database reloads records added or changed externally. There is no required working copy. **Create Backup** is a separate manual snapshot. **Export Copy As** creates an independent MDB without changing the active selection. Legacy Default Database and Current Copy paths are not automatically activated after upgrading: explicitly choose the MDB you intend to edit. If the file changes externally after opening, saving is blocked until you refresh. Close TEW IX\'s database editor while using this application; do not edit the same MDB simultaneously. **No entity insert or delete operations are performed.** Existing IDs and linked references are protected.
