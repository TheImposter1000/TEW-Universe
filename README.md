# TEW Universe Studio

Independent Windows desktop editor for **existing** Total Extreme Wrestling IX scenario records.

## Tag Teams module

The sidebar now includes **Tag Teams**, integrated into the existing three-column workspace. You can search existing `tblTeam` records, edit their supported fields, and select linked workers and companies from actual `tblWorker` and `tblFed` records. Team-type values remain **raw numeric codes**, drawn from existing teams in the selected MDB until the numeric mapping to Permanent Unit, Unit, and Individuals is verified.

**Create Tag Team** opens a dedicated editor for a pair of existing workers, company-specific or game-wide affiliation (using only None codes observed in this MDB), team-type code, experience, formation, finisher, and active state. A manual **Create Backup** is required before creating a team. The app validates the MDB schema, linked IDs and duplicate partnerships, then inserts exactly one new `tblTeam` row transactionally, allocating a unique UID and Recordname. Unsupported mandatory schema fields block creation; no tables besides `tblTeam` are modified.

This initial module must be tested in TEW IX's Data Check using a backed-up scenario before editing your main scenario. Its form fields and mappings may be adjusted as MDB-specific details are validated.

## Desktop application

The published Windows app now uses **WPF and .NET 8**. Its source is in `src/TEWUniverse.Desktop`, sharing the existing Access data layer and settings from `src/TEWUniverse.Studio`.

The worker portrait feature looks for a **worker-name PNG first**, then WebP/JPEG/GIF/BMP files in that order, in the configured local pictures folder or its `People` subfolder. If no usable worker-name image exists, it falls back to the stem of the worker's `tblWorker.Picture` filename, with PNG still preferred. Missing images show the silhouette; loaded images hide the silhouette and its background, preserving PNG transparency. Portrait loading never edits the MDB or image files. WebP requires a compatible Windows image codec.

Worker fields that store numeric TEW IX enumeration values, including Gender, Nationality, Based In and Wrestling Style, are displayed consistently as their original codes. The profile editor also accepts their raw stored codes rather than mixing in translated dropdowns. Boolean flags such as Active remain Yes/No controls.

The redesigned Workers screen includes a sidebar, searchable worker list, real MDB fields, biography editor and status bar. Companies, Titles (championships), Events, and Stables now have existing-record editors in the same dark workspace. These sections browse existing MDB entries and allow updates to a restricted set of fields. Relationships, History and Tools remain nonfunctional placeholders until relationship and title-lineage operations are validated.

In Titles, open **Title Lineage** to view existing pre-game reigns from `tblBeltPreHistory`, filtered by the selected championship and sorted by Order Number where the MDB schema identifies it. A Generate Title Reigns panel lets you select a pool of existing workers, reign count, years and singles/tag-team mode, then generate a dated preview and export a draft CSV. You can replace holders and dates ONLY when the selected championship already has exactly the same number of prehistory rows; this updates only that belt's existing history UIDs in one transaction. Nothing is inserted or deleted. Always back up before replacing lineage; the exported draft CSV is not a verified TEW IX import file. If the belt-reference column cannot be recognized unambiguously, the app shows diagnostic columns rather than mixing reigns across belts.

Titles now also includes an **Advanced Generator** tab: select existing workers by UID (optionally using historical ring names) or add historical name-only champions with `Holder1=-1`. Specify their eligible years in the company and the exact number of required reigns. The planner reserves these reigns within their eligibility windows, then can fill the remaining slots using eligible background holders loaded from the selected title's existing MDB history. A preview and CSV export work for any proposed number of reigns; applying the draft is restricted to the existing rows of that championship, without inserting records. This advanced generator currently handles singles histories and requires a backup before replacing records.

**Varied championship reigns:** Standard championships no longer automatically change hands on January 1 or award every champion an identical year-long reign. The Advanced Generator now picks variable durations—including a few weeks, several months, and occasional reigns lasting more than a year—while preserving every fixed winning **year** supplied for a real superstar. The number of generated reigns emerges from this chronology, instead of one history entry per calendar year. Defence counts are also varied independently of reign duration. The preview shows days held and a short/medium/long breakdown. The older fixed-count generator also allocates its requested number of reigns across uneven durations. **Annual tournaments** produce one winner per year on a date calculated from a recurring schedule (month, first/second/third/fourth/last occurrence, weekday), without a title-loss reign or defences.

**Expanded title editing:** Additional `tblBelt` fields are now real editable controls rather than a read-only list. Settings such as **Annual Title**, **Annual Type**, **Tour Frequency**, **TV Frequency**, **Retain Title**, **Achievement**, **Valid Matches**, and **Belt Lock** can be changed using their stored MDB data types when present. Title UID, internal record names and unknown foreign-key fields remain protected. **Original Fed** and **Card UID** accept existing linked IDs (with zero / -1 unassigned sentinels), checked against `tblFed` or `tblCard` before saving. All edits use the normal Save Changes transaction and pending-change tracking. No automatic backup is created; use Create Backup before editing an important scenario. Title Classification is still a separate cosmetic setting saved locally, not a fake TEW IX enum.

**Championship vs. annual tournament:** Title Details now has an app-only **Title Classification** selector for each championship UID in each scenario database. The label is saved locally in TEW Universe Studio settings, not written into `tblBelt`. **Championship** continues to show reigns, loss dates, and defences. **Annual Tournament / Cup** represents one winner for each annual edition: the generator asks for the event month and weekday occurrence (for example, the first Sunday in March) and computes `BeltCaptured` separately for each year's edition, and uses the title-history no-reign conventions visible in existing TEW IX data (`BeltLost = 1666-01-01`, `Defences = -1`). The lineage table displays winners rather than treating them as champions with year-long reigns. The old reign-based generator is blocked for tournament-classified titles. The title editor also includes an expanded read-only inspector of other `tblBelt` fields and additional allowlisted descriptive fields; IDs and foreign key relationships remain protected. This is a Studio display classification, not an assertion that TEW IX stores these types itself. Test generated tournament history on a backed-up scenario before writing to the primary MDB.

**Two-section history generator:** In **Titles → Advanced Generator**, the top **Superstars** section contains only linked workers, their optional historical ring names, active years, reign counts and exact winning years. The lower **NPC History** section contains just the historical start/end years and optional race/gender codes; there is **no NPC reign-count field**. The generator automatically creates a name-only NPC winner in each year without a pinned superstar victory, drawing names from `tblGenerateWorker` and never adding workers. For example, a cup that began in 1994 with Kaito Moriyama's sole 2020 victory produces a full chronology across the chosen years, not a one-row preview. Rebuilding the selected belt still requires a backup, confirmation and successful schema checks. History inserts have not yet been validated in-game.

**Fixed-win history builder:** The Advanced Generator now accepts exact championship-winning years for linked workers, for example `2016, 2017, 2019` for Dragonheart (`#4975`). It reads name-only NPC candidates from `tblGenerateWorker`, optionally filtering by stored race/gender codes, and generates a chronological sequence with NPC champions before, between, and after those fixed wins. NPC champions are written with `Holder1=-1` and a historical display name; no NPC is added to `tblWorker`. The preview shows the implied predecessor and successor of each champion. A full rebuild can **DELETE the selected championship's old `tblBeltPreHistory` rows and INSERT any requested number of new rows in one transaction** (other championships and workers are not changed). The **Import Preview to Title Lineage** action performs this destructive replacement for the selected title only, requires an on-demand **Create Backup** and explicit confirmation, then opens the saved Title Lineage view so the results are immediately visible. The table schema is validated at runtime, and unsupported schemas fail without writing. Validate a test database with TEW IX's Data Check before editing production data.

**Direct database editing:** Select an existing scenario MDB as the **Active Database**. Save Changes writes to that same file; Refresh Database reloads records added or changed externally. There is no required working copy. **Create Backup** is a separate manual snapshot. **Export Copy As** creates an independent MDB without changing the active selection. Legacy Default Database and Current Copy paths are not automatically activated after upgrading: explicitly choose the MDB you intend to edit. If the file changes externally after opening, saving is blocked until you refresh. Close TEW IX\'s database editor while using this application; do not edit the same MDB simultaneously. **No entity insert or delete operations are performed.** Existing IDs and linked references are protected.

## Distribution

Get the Windows installer from [GitHub Releases](https://github.com/TheImposter1000/TEW-Universe/releases). GitHub Actions builds WPF, the installer and update agent. Microsoft ACE OLE DB for 64-bit Windows is required for Access MDB connections.

The explicitly selected scenario database is edited directly. Credentials are not in source code; optional password remembering uses local Windows-user DPAPI encryption.

See [development notes](docs/DEVELOPMENT.md) for build instructions and validation guidance.
